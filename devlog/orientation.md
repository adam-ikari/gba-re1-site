# 侧面也得是丧尸: 掠射面的盐椒

上一轮的报告是两句话: **"模型渲染效果太差"** 和 **"使用丧尸正面演示"**。
把第二句按字面做(把所有东西都转正)是错的 —— 追问之后拿到的口径是 **"全部不同方向和姿态"**,
而"太差"具体指 **"朝向: 只有正面认得出是丧尸"**。

> **并排比较的图已从这一页撤下嵌入** —— 页面只放单幅画面, 每张仍标 `B#` 归属。撤下的文件都在仓库里,
> 线上 `/img/<名字>.png` 仍可取(未做物理删除), 完整清单与理由见 [数字总表 → 版本登记](/data#版本登记)。

这句话里有两个命题, 成本完全不同, 所以先拆开:

| 命题 | 判据 | 结论 |
|---|---|---|
| 侧面**轮廓**不像丧尸 | 逐格落笔像素数、内容宽 | 几何本来如此, 不是 bug |
| 侧面**更碎** | 逐格相邻亮度跳变、孤立点占比 | **是真 bug**, 而且不止侧面 —— 动画后段全朝向都碎 |

先给第一条一个数, 免得它一直挂在"渲染效果差"里: 同一姿态(0)、同一机位, 正面落笔 **910 px /
内容宽 26**, 侧面 **529 px / 内容宽 16**。侧面少 42% 的像素是**一个人侧过来的必然结果**,
而头两档都在(头顶 4 行里最宽的一行: 正面 5 px / 侧面 7 px, 侧面的头是往前倾的; 颅骨投影
5.6 px, 见[一颗消失的头](/devlog/texture-uv))。这条不改。

![正面与侧面的轮廓 · **B4**(纹理仍 NEAREST)](/img/orient_silhouette.png)

第二条改完了。这一页记的是它为什么只在某些姿态出现、门槛怎么选、以及**我先是把根因猜错了**。

## 1. 先把"全部朝向 x 全部姿态"变成一张能看的表

"只有正面认得出"这种话不能靠引用, 得摊开看。做法: 8 个八分位朝向(0/32/../224) x 31 个骨骼
姿态 = **248 格**, 每格都是近档 32x64。

关键是**像素全部由 GBA 自己渲**: 每格走 `-DZS_BAKE` 的 `zs_bake_poses()`, 它调的就是
`render_zombie_model` 本身 —— 同一台相机、同一个光栅器、同一份调色板。主机侧只做一件事:
把 8bpp 图块按当次构建 dump 出来的 OBJ 调色板解成 RGB。那是纯查表, 不含任何几何, 所以
表上看到的每个像素都是真机像素。

一张表 248 格要 32 次独立构建(精灵区只有 16 KB, 近档一格 2048 B = 一批 8 格, 一个 yaw 四批),
所以它是个**批处理工具**而不是随手一跑的东西 —— 也正因为贵, 每格顺手记下标量:

```bash
python3 tools/orient_sweep.py --yaws 0,32,64,96,128 --extra "-DZB_GRAZE_TEXELS=4" \
        --out /tmp/sheet.png --zoom 5
# -> /tmp/orient_stats_DZBGRAZETEXELS4.tsv  (yaw, pose, 像素, 外接框, 头顶最宽, 横跳变, 纵跳变, 孤立点)
```

产线其实只渲 5 个桶, 224/192/160 是用 OAM attr1 bit12 把 32/64/96 **水平翻**出来的(见下面第 6 节)。
所以接触表按产线口径摆:

![8 朝向 x 7 姿态接触表 · 内容属 **B6**: 这张表随 B4 那轮入库, 后来在 B6 的提交里被重生成过](/img/orient_sheet_prod.png)

## 2. 根因: 掠射面每像素跨过的纹素多于一个

碎的不是"侧面", 是**动画后段**(姿态 24..30, 弯腰挥臂那几帧)在**所有朝向**上一起碎:

| 姿态段 | 横跳变中位 | 横跳变 p90 | 孤立点中位 |
|---|---|---|---|
| 0..23(前中段) | 8.1 | 10.1 | 2.8% |
| 24..30(后段) | **15.4** | **20.2** | **4.8%** |

(3 个直渲朝向 x 31 姿态 = 93 格, 同一构建只改过滤开关。)

后段躯干相对相机倾下去, 衬衫那批面变成**掠射**。掠射面的问题是: 它是仿射 UV, 一个面在屏幕
上占几列, 但在纹理上跨过的纹素数可以远多于每列一个。32x64 的纹理铺在 0..4096 的 UV 上,
一个面 128 个纹素宽只投影到 6 列, 就是 **~21 纹素/像素**。逐像素取色于是每一步都跳过一个
纹素带 —— 而那些被跳过的纹素**在 32x64 的精灵上根本没有像素能显示它们**。
采出来的不是"模糊", 是从一条纹理带里每像素随机抽一个颜色: 盐椒。

判据因此不是"这个面斜不斜", 而是**每像素跨几个纹素**。超过 4 就整面平涂(采重心 UV 那一个
纹素), 梯度置零、深度照常插值:

```cpp
const fixed lim = ZB_GRAZE_TEXELS * (4096 / ZB_TEX_W);   /* 4 纹素/像素 */
fixed gu = gs_du < 0 ? -gs_du : gs_du;
fixed gv = gs_dv < 0 ? -gs_dv : gs_dv;
for (int g = 0; g < 3; g++) {                 /* 跨度按三条边取最大 */
    fixed au = iu[g] < 0 ? -iu[g] : iu[g];
    fixed av = iv[g] < 0 ? -iv[g] : iv[g];
    if (au > gu) gu = au;
    if (av > gv) gv = av;
}
if (gu > lim || gv > lim) {
    gs_ufix = (U[0] + U[1] + U[2]) / 3;       /* 整面退化成重心那一个纹素 */
    gs_vfix = (V[0] + V[1] + V[2]) / 3;
    gs_du = gs_dv = 0;
    gs_flat = 1;                              /* 深度照常插值, 轮廓一个像素不少 */
}
```

**两个方向都要查, 而且跨度要按三条边取最大**: 只量每像素梯度 `gs_du` 会漏掉"竖着薄"的那批面
—— 它每行跨过很多纹素、逐像素却几乎不动, 于是躲过门槛, 表现成身上凭空多出一条**深色竖带**
(yaw 192 实测如此; 64 是它的镜像朝向却干净, 因为漏的那几面在模型另一侧)。

## 3. 门槛不是调出来的, 是被两张图逼出来的

| 门槛(纹素/像素) | 全体 93 格横跳变中位 | 正面 yaw 0 的样子 |
|---|---|---|
| 不开 | 8.4 | 盐椒 |
| 2 | 最漂亮(正面 → 0.0) | **衬衫一整块灰**, 背带和纽扣没了 |
| **4** | 6.1 | 背带、纽扣、明暗都在 |
| 8 | ≈ 不开 | 没动 |

门槛 2 的**数字是这三行里最好的**, 而它是错的。这就是这条量尺的坑: 相邻亮度跳变的中位数
**奖励模糊** —— 把整张图平涂能让两个轴一起归零。所以任何一次 A/B 都必须同时报**逐格落笔像素**
和**摊开的接触表**, 只看跳变会一路选到最糊的那一档。

同一把尺子在反方向上也骗人: 后段那批噪声在过滤后中位只剩 7.1, 但 p90 才暴露残留 ——
中位数被大片平坦区(裤子、衬衫本体)的零跳变对拉下去了。

无过滤 / 门槛 2(过头)/ 门槛 4(采用)三档落在同一 yaw 0、同一姿态 27 上。那张三档并排图已撤下嵌入,
三档的读数在上面的表与 §5 里 —— "过头"那一档的代价是**平的**: 衬衫整块没有对比。

## 4. 我先猜错的那次: 把"除法"当成了根因

第一个假设很体面: 梯度是 `sg * rc_div(Δ, ddx)` 算出来的, 当分子是两个 UV 差相减、分母是
两个 x 差相减时, 两边都接近 0 —— 教科书上的**灾难性抵消**。于是我写了一版探针: 判定面与像面
近平行时改走平涂。

它在算术上就不成立。UV 和 x 都是定点数, 相减的舍入误差各 ≤ 1 个 Q12 单位, 所以分子的相对误差
≤ 1/|分子| —— 只有 |分子| 本身就小的时侯才谈得上"抵消", 而那种面(投影宽度不到 1 个单位)
**早被 `|ddx| < 256` 那条快速通道接住了**, 走的是 `gs_du = gs_dv = 0`, 根本不做除法。
也就是说: 这个理论能命中的那批面, 光栅器本来就在平涂它们; 而表上那 15.4 的噪声格, 按这条
理论根本不该出现。理论连"要解释的现象"都对不上, 所以顺着它写的那版探针也一起作废了 ——
它没有留下一个能预测下一格的判据。

真正的原因(第 2 节)是**采样密度不足**, 不是精度损失 —— 它跟定点位数无关, 所以后来试"把深度
从 8 位放宽"也自然无效:

| 改动 | 全体 93 格横跳变中位 | 后段 21 格 |
|---|---|---|
| 基线(8 位深度) | 8.4 | 15.4 |
| `ZS_Z_SHIFT=4`(12 位) | **9.5** | **17.0** |
| `ZS_Z_SHIFT=6`(10 位) | **9.6** | **17.5** |
| UV 越界钳到纹素内 | 8.0 | 13.8(几乎没动) |

放宽深度**更脏**, 钳 UV 基本没动。三条一起把"数值精度"这一族解释全部排除掉, 只剩"每像素
纹素数"这一条能同时解释: 为什么后段比前段碎、为什么平涂能治、为什么加深位数不能治。

## 5. 结果与代价

采用门槛 4, 93 格 A/B(同一构建、只改 `-DZB_GRAZE_TEXELS`):

| | 前中段 72 格 | 后段 21 格 |
|---|---|---|
| 横跳变中位 | 8.1 → **5.3** | 15.4 → **7.1** |
| 横跳变 p90 | 10.1 → **8.0** | 20.2 → **8.0** |
| 孤立点中位 | 2.8% → **2.0%** | 4.8% → **3.3%** |

**没有一格变差**: 59 格改善 > 2, 34 格不动, 0 格变差 > 2(最坏 +0.0)。
落笔像素 63 格不变 / 28 格变多 / 2 格变少, 最坏 **−1 px**, 93 格合计 **+35** —— 平涂顺手
补了原来采到透明纹素留下的小洞。头顶最宽逐格不变(6 px)。

代价侧, 用发布配置(`-DZS_CROWD_BENCH -DZS_REAL_SCENE=ON`, 6 只同屏)量了两版:

| 两版只差门槛开关(**B3 → B4**) | 稳态周期/硬件帧 | 进场预热(一次性) | ROM text |
|---|---|---|---|
| 门槛 1000000(不过滤) | 20,752 | 111,742,594 cyc = 6.660 s | 473,640 B |
| **门槛 4(采用)** | **20,752(逐字节相同)** | 111,672,571 cyc = 6.655 s | 473,632 B |

稳态不动是**结构性的**: 群戏稳态是姿态缓存全命中(0 填充 + 1 次 DMA 换入), 光栅器根本不参与,
所以任何逐像素改动都不可能动稳态。预热 −0.06%(噪声级, 方向上还略降 —— 平涂面少了逐像素乘法)。
**这句"免费"只对周期成立。** 下一轮[造了一把问"对不对"的尺子](/devlog/correctness)之后, 平坦化
在颜色上的价格量出来了: 16 格、当时那份烘焙(**B6**: 面积平均 + blur 1.2)、两把尺子分别给 **+2.53 / +2.4**(0–255, 相对理想采样参照;
第一次在 4 格、旧烘焙上量的是 +0.7…+4.9, 量级一致)。它仍然是笔划算的交易, 但不再免费 ——
见该页第 5 节。

> **这一页(§2–§5)的跳变/孤立点数字全部是在 NEAREST 烘焙上量的**, 当时纹理还没换。之后烘焙换了两次
> (NEAREST→面积平均→面积平均+blur 1.2), 每一格的绝对值都随之变了, 但**方向没变**: 门槛 4 之下
> 后段仍然比前中段碎, B6 上前中段横跳变中位已降到 0.91、后段仍是 8.00(见第 7 节末)。

> **另一条更关键的口径变更(第八轮 = B9/B10 候选)**: 这一页写的"超过 4 就整面平涂"只覆盖了**扫描线通路**。外接框 ≤16
> 候选像素的小面走另一条每面只除一次的通路, 它**一直不过这道过滤** —— 而这 758 面的模型里多数面恰好是小面
> (~0.7 px 宽的细长条)。所以 §5 那张 8.1→5.3 的表量的是"一半的面被治好、另一半没人管"。门槛补进小面通路之后,
> 全 248 格横跳变中位 3.17→**2.39**、纵跳变 0.91→**0.00**、0 格丢像素, 且这是**两把尺子第一次同向变好**。
> 数、图与"把整条通路关掉会把跳变压到 0.00 那是退化解"这条陷阱, 见 [对不对 §10](/devlog/correctness)。

真场景里的同一帧(ROOM1036, 六只, 第 900 帧, 两版**姿态相同**; 两边并排的图已撤下嵌入):

整帧只变 **576 / 38,400** 个原生像素(1.5%), 全部在精灵层 —— 背景、调色板、落位一个字节没动。
变的这 1.5% 里, 近档那一只的衬衫从"每像素独立取色"变成一块能读出的浅色。

## 6. 镜像边界: 过滤之后仍在, 但方向出人意料

产线只渲 5 个桶, 224/192/160 由硬件水平翻转 32/64/96 得来。这条免费的边界一直有个隐忧:
**镜像假设两侧一样干净**, 而掠射是几何事实, 不会因为翻转而消失。

水平翻转对"相邻亮度跳变的集合"是保序的(只是把左右顺序倒过来), 所以量这个不用新构建:
直渲 192 与直渲 64 的差, 就是"直渲"与"产线镜像"的差。门槛 4 之下:

| 镜像对 | 直渲比镜像源脏 > 2 的姿态 | 差中位 | 最大 |
|---|---|---|---|
| 192 ↔ 64 | 14 / 31 | +1.5 | +10.8 |
| 160 ↔ 96 | 17 / 31 | +2.3 | +6.6 |
| 224 ↔ 32 | 19 / 31 | +2.5 | +8.0 |

边界**没有被关闭**, 只是变窄了。但方向要说清楚:
是**直渲那份更脏, 产线用的镜像那份更干净**。所以镜像不是"省下来的将就", 它同时是更好看的那
一个选择 —— 反过来说, 哪天要改成 8 桶直渲, 这三个角会立刻比现在脏一档, 那笔账得重算。

yaw 192、姿态 19 —— 差最大的一格(直渲 16.4 对镜像源 5.6, 落笔像素反而**少** 7 个, 孤立点却只差
0.3 个百分点: 脏在"逐像素跳变", 不在"点多不多")。

**上面这张表和这一格的读数都是 NEAREST 烘焙时代的**。换烘焙会改这个边界, 所以按同一把尺子(横跳变中位,
全直渲 248 格表, 门槛 4)在两份干净表上重量了一次:

| 镜像对 | NEAREST(**B1–B4**, 上表) | 面积平均(**B5**) | 面积平均 + blur 1.2(**B6**) | 足迹平均 + 已剥幽灵(**B7**, 群戏画面与出货 **B8** 逐位相同) |
|---|---|---|---|---|
| 192↔64 | 14/31, 中位 +1.5, 最大 +10.8 | 27/31, +2.7, +9.5 | **15/31, +1.5, +7.1** | **19/31, +2.4, +7.7** |
| 160↔96 | 17/31, +2.3, +6.6 | 20/31, +2.7, +5.6 | **11/31, +1.4, +5.6** | **0/31, −0.8, +1.6** |
| 224↔32 | 19/31, +2.5, +8.0 | 11/31, +1.0, +5.6 | **6/31, +0.0, +3.3** | **6/31, +0.9, +2.7** |

最后一列是 B7 之后重量的(同一把尺子、两份干净的全直渲 248 格表, **没有新增构建**; 上一列在新表下
逐字重现, 所以两列可比)。**这一轮边界不统一, 那句"三对里都是直渲那份更脏"要改口**: 192↔64 变宽
(15→19 格), 224↔32 微开(0.0→+0.9), 而 **160↔96 不仅关掉还翻了向** —— 差中位 −0.8 意味着直渲 160 比
它的镜像源 96 **更干净**, 拿 96 翻转去替 160 现在是净损失。总方向仍然支持省("镜像那份不更脏"两对成立、
一对反过来), 但"哪天改 8 桶直渲"的账变了: 只剩 192↔64 一处是真代价(差最大 pose 23, 直渲 8.00 对
镜像源 0.33, 落笔像素 513 vs 515 —— 又一例"脏在跳变不在点")。

旧结论里"边界随过糊变窄"仍然对(那是 blur 那一步的账), 只是**换代表色把它往回推了一格**:
B7 整体在跳变尺子上更脏(见[对不对 §8.5](/devlog/correctness)), 因为剥掉幽灵像素后每格少落 45 px。

## 7. 还剩什么

- **后段姿态仍然比前中段脏, 而且在 B7 上格外扎眼**: 过糊(blur 1.2)把前中段 192 格抹到横跳变中位
  **0.91**、孤立点 0.6%, 后段 56 格仍是 **8.00** / 1.6%(NEAREST 烘焙 + 同一道门槛时是 5.3 / 7.1,
  孤立点 2.0% / 3.3%)。
  门槛 4 治的是"每像素跨几十个纹素"那批面, 跨 4~20 个的那批还在逐像素采样 —— 那批面平涂不了
  (平涂会把整块衬衫变成一块灰), 过糊也只能压住它们的一部分。
- **这一页的全部跳变读数后来又被重新定价了一次**(B7: 掠射面的代表色从重心纹素换成足迹面积平均,
  外加剥掉跨度外扩的幽灵像素)。B7 在同一把尺子上**两段都更脏**: 前中段 0.91 → **2.39**、
  后段 8.00 → **10.07**、248 格整体 2.39 → **3.17**, 归零格 84 → 58。孤立点没变差(0.008 → 0.007),
  落笔像素中位 801 → 756 —— 少落的正是那些画在三角形外面的脏像素。
  **"更脏"这一句只在这把尺子上成立**: 换到对参照正确性的尺子(渲染偏离 12.04 → 9.49、IoU 0.912 → 0.970)
  方向是反的。教训写在对不对那一页: **跳变类指标奖励"多落笔把洞填上", 它不能单独当验收**。
- 掠射面平涂之后, 那些面**本来在 32x64 上就显示不出**的纹理细节确实没了, 只剩面与面之间的
  色差。这是这笔交易的付款方, 图上不显, 但得记着。
- 接触表是 32 次构建换的(一个 yaw 四批)。它不该被随手跑, 所以门槛扫描只跑了
  3 个直渲朝向(93 格), 没有 8 桶全扫。
